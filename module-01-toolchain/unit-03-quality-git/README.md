## 三层防线

质量保障不靠自觉，靠三道自动关卡：

| 时机 | 动作 | 工具 | 拦得住什么 |
| --- | --- | --- | --- |
| 写代码时 | 编辑器实时提示 | ESLint 插件 | 未使用变量、错误的 API 调用 |
| 保存时 | 自动格式化 | Prettier | 缩进、引号、尾逗号不统一 |
| 提交时 | `pre-commit` 钩子校验暂存区 | husky + lint-staged | 带问题的代码被提交进去 |
| 推送后 | 流水线再跑一遍全量检查 | CI | 绕过本地钩子（`-n`）的提交 |

> 提交时钩子只对暂存区文件跑检查，速度快；流水线跑全量，防止有人绕过钩子。两层都要有。

## 提交信息规则

```
<type>(<scope>): <subject>
```

`type` 取 `feat`、`fix`、`docs`、`style`、`refactor`、`chore`、`test`。

`scope` 写单元号，方便按单元回溯提交记录：

```
feat(u05): 待办清单支持按状态筛选
fix(u02): 修正 vite 代理配置导致的接口 404
docs(u01): 补充环境自检清单
```

`subject` 用中文、祈使句、结尾不加句号。

## 分支约定

| 分支 | 用途 |
| --- | --- |
| `main` | 稳定分支，只接受通过流水线的合并 |
| `feat/u<单元号>-<简述>` | 单个单元或功能的开发分支 |
| `fix/<简述>` | 问题修复分支 |
